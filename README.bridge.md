# پل آیفون

مشخصات آیفونِ وصل‌شده با کابل را می‌خواند و روی `127.0.0.1` می‌گذارد تا
فرم **ثبت کالا** بتواند بخواندش.

راهنمای کاربر داخل خودِ برنامه است: **کالا و انبار ← ثبت گوشی تازه ←
راهنمای خواندن از کابل** (`/devices/scan/bridge`). این فایل یادداشت
توسعه‌دهنده است.

## چه می‌دهد

از `lockdown` — همان چیزی که iTunes می‌خواند، بدون Developer Mode:

| فیلد | کلید دستگاه |
|---|---|
| نام دستگاه | `DeviceName` |
| نام بازاری | از `ProductType` و جدول `IRECV_DEVICES` خودِ pymobiledevice3 |
| شناسه‌ی مدل | `ProductType` |
| ظرفیت | `com.apple.disk_usage` → `TotalDiskCapacity` |
| نسخه‌ی iOS | `ProductVersion` + `BuildVersion` |
| سریال | `SerialNumber` |
| IMEI و IMEI2 | `InternationalMobileEquipmentIdentity[2]` |
| UDID | `UniqueDeviceID` |
| منطقه و پارت‌نامبر | `RegionInfo` + `ModelNumber` |

از `IORegistry` (سرویس diagnostics) — کلاس `IOPMPowerSource`:

| فیلد | از |
|---|---|
| سلامت باتری | `NominalChargeCapacity ÷ DesignCapacity` (روی iOS قدیمی‌تر `AppleRawMaxCapacity`) |
| تعداد شارژ | `CycleCount` |
| شارژ فعلی | `CurrentCapacity` |

باتری **اختیاری** است: اگر دستگاه ندهد، بقیه‌ی مشخصات از دست نمی‌رود.

## چه نمی‌دهد، و چرا

**رنگ.** اپل کدی مثل `1` یا `#3b3b3c` می‌دهد که نگاشت پایداری به نام
بازاری («Deep Blue») ندارد و از مدلی به مدل دیگر عوض می‌شود. پس `color`
همیشه `null` است و کد خام زیر `colorCodes` می‌آید. **حدس زده نمی‌شود** —
یک رنگ اشتباه در دفاتر بدتر از رنگِ خالی است، چون کسی به آن شک نمی‌کند.

به همین دلیل `MobileGestalt` هم استفاده نمی‌شود: اپل از iOS ۱۷.۴ منسوخش
کرده و خودِ pymobiledevice3 رویش استثنا پرتاب می‌کند.

## اجرا

```bash
pip install -r requirements.txt

python -m iphone_bridge            # سرور، روی 127.0.0.1:17377
python -m iphone_bridge read       # یک بار بخوان و JSON چاپ کن
python -m iphone_bridge selftest   # بدون گوشی، خودت را بسنج
```

`--allow https://panel.example.com` صفحه‌ی دیگری را هم مجاز می‌کند.

## ارسالِ مبلغ به کارتخوان

همان فایلِ اجرایی، با دو گزینه‌ی تازه، مبلغِ فاکتور را به کارتخوان هم می‌رساند (`iphone_bridge/pos/`):

    iPhoneBridge.exe --pos-server https://novo.stland.ir --pos-token <رمز>

رمز در Novo، «خزانه ← ارسال به کارتخوان ← ساختِ رمز برای پل» ساخته می‌شود. پل هر ثانیه و نیم از سرور می‌پرسد؛ هیچ درگاهی
روی رایانه باز نمی‌شود. هر شرکتِ پرداخت یک راه‌انداز در `pos/drivers.py` دارد (کلید = `POS_PSP`)؛ شرکتی که هنوز راه‌انداز
ندارد «رد — هنوز وصل نیست» می‌گیرد و چیزی به دستگاه نمی‌رود.

## ساخت EXE

روی یک ماشین **واقعی ویندوز** در CI ساخته می‌شود
(`.github/workflows/bridge.yml`)، نه اینجا: بعد از ساخت بلافاصله
`selftest` روی خودِ فایل اجرایی اجرا می‌شود، تا اگر PyInstaller ماژولی
را جا انداخته باشد همان‌جا معلوم شود نه روی کامپیوتر فروشگاه.

فایل از بخش Actions مخزن، به اسم `iPhoneBridge-windows` دانلود می‌شود.

بعد از هر ساختِ تازه، یک بار در پنل بگذاریدش:
**کالا و انبار ← ثبت گوشی تازه ← راهنمای خواندن از کابل**. از آن به بعد
همه از همان‌جا می‌گیرندش و کارشان به گیت‌هاب نمی‌افتد. فایل روی والیوم
`/data` می‌نشیند، نه داخل مخزن یا ایمیج — ۶۱ مگابایت است و هر ساختِ تازه
همان‌قدر به تاریخچه‌ی گیت اضافه می‌کرد.

### چیزی که ساختِ EXE را دو بار شکست

هر دو بار فایل ساخته شد و `--version` هم جواب داد؛ اولین ایمپورت واقعی
شکست. **ساختِ روی لینوکس هیچ‌کدام را نشان نمی‌دهد** — نگهبان،
`selftest` روی خودِ EXE ویندوزی است و `tests/test_packaging.py`.

**۱. chardet.** با mypyc کامپایل شده. روی لینوکس PyInstaller اتفاقی
نسخه‌ی `.py` را برمی‌دارد و کار می‌کند؛ روی ویندوز `.pyd` را برمی‌دارد و
آن دنبال `language__mypyc` می‌گردد که داخل فایل اجرایی نیست. خطایش
`SystemError` است، نه `ImportError` — پس `except ImportError` خودِ
requests هم نمی‌گیردش و کل ایمپورت `lockdown` می‌ترکد. زنجیره‌اش:
`lockdown → service_connection → utils → requests → chardet`. حالا
chardet در `excludes` است و `charset_normalizer` جایش را می‌گیرد. پل
اصلاً درخواست HTTP نمی‌فرستد.

**۲. ماژول‌های ویندوزی.** `lockdown.py` همان لحظه‌ی ایمپورت
`get_os_utils()` را صدا می‌زند، و آن روی ویندوز
`pymobiledevice3.osu.win_util` را می‌آورد که به pywin32 (`win32security`)
و `ifaddr` تکیه دارد. هیچ‌کدام در کدِ ما ایمپورت نمی‌شوند، پس ردیابی
معمولی پیدایشان نمی‌کند. صریح در spec آمده‌اند.

دستی:

```bash
pip install pyinstaller
pyinstaller --clean --noconfirm iPhoneBridge.spec
./dist/iPhoneBridge selftest
```

## امنیت

پل فقط روی `127.0.0.1` گوش می‌دهد — هیچ‌کس از شبکه نمی‌رسد.

ولی «لوپ‌بک» یعنی هر برنامه‌ای روی همین کامپیوتر، **از جمله هر صفحه‌ی
وبی که کاربر باز کرده**. پس مبدأ مرورگر باید در فهرست `DEFAULT_ORIGINS`
باشد وگرنه ۴۰۳ — و این رد کردن **پیش از** سراغ گوشی رفتن است، تا یک
سایت مهاجم حتی نتواند پیغام Trust را روی گوشی بیاورد.

فقط همان فیلدهای بالا بیرون می‌روند، نه هر چه دستگاه گفت: کلید عمومی و
مک‌آدرس و بقیه اصلاً از `LOCKDOWN_KEYS` رد نمی‌شوند.

## قرارداد با برنامه‌ی وب

`contract/iphone-sample.json` را همین کد می‌سازد و **هر دو طرف** از آن
می‌خوانند:

* `tests/test_contract.py` می‌سنجد که خروجی پل هنوز همان است؛
* `tests/unit/iphone-device.test.ts` سمت وب را روی همان فایل می‌سنجد؛
* `tests/e2e/iphone-bridge.test.ts` پلِ واقعی را با
  `BRIDGE_FAKE_DEVICE` بالا می‌آورد و کل زنجیره را در مرورگر می‌سنجد.

اگر شکل خروجی عوض شد:

```bash
cd bridge && python -m tests.test_contract
```

## آزمون

```bash
python -m pytest
```

آنچه سنجیده می‌شود: تبدیل مقدارهای خام دستگاه، ریاضی باتری، ترجمه‌ی
خطاها به فارسی، و فهرست مبدأ. آنچه سنجیده **نمی‌شود** و فقط با آیفون
واقعی معلوم می‌شود: خودِ گفت‌وگو با دستگاه روی USB.
